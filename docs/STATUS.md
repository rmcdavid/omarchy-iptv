## Defects

Format: `<id> | severity | task | repro | state`. Severity is P1 to P4; P4
means diagnostic-only, visible to nobody but a maintainer reading a log.
State must NAME a state: open, fixed, verified fixed, accepted, superseded,
wont fix. `fixed` means a commit repairs it. `verified fixed` means QA re-ran
the original repro afterwards and said so, and the row cites where. A release
having shipped is not a state.

Ids are `D-` for a defect and `F-` for a finding. The distinction is tone, not
obligation, and `scripts/check-defect-ledger.py` treats them identically:
every id written into any tracked markdown file must have a row here carrying
a severity and a state, or `scripts/check.sh` is red (CLAUDE.md rule 13).
